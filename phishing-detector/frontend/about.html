Machine Learning-Based Phishing Website Detection System

A production-styled cybersecurity application that classifies URLs as safe, suspicious, or phishing using a Random Forest classifier, served through a Flask REST API.

Project overview

SentryNet analyses a submitted URL and returns a verdict — safe, suspicious, or phishing — in under a second. Rather than relying on static blocklists, which fail against newly-registered domains, the system extracts a feature vector from the URL's structure and host, and classifies it with a trained Random Forest model.

The result isn't just a label. Every scan returns a confidence score, a full breakdown of which features drove the decision, a human-readable explanation of the risk, and — where relevant — the likely brand being impersonated along with a link to the real site.

Objectives

  • Design and train a supervised machine learning model capable of distinguishing phishing URLs from legitimate ones using lexical and host-based features.
  • Build a REST API that serves predictions with low latency, decoupled from the frontend.
  • Present results transparently — showing the reasoning behind a verdict rather than a single opaque label.
  • Detect brand impersonation using string-similarity matching against a trusted domain registry.
  • Provide analytics over scan history so patterns in threat volume become visible over time.
  • Package the whole system with professional UX and code structure suitable for real-world extension, not just a classroom demo.

Research motivation

Phishing remains one of the most common initial access vectors in reported security incidents, precisely because it targets people rather than infrastructure. Blocklist-based defences are reactive by design — a domain has to be reported and confirmed malicious before it's blocked, by which point a campaign has often already succeeded.

Machine learning approaches instead generalise from the structural properties of known phishing URLs — how they're built, not just which specific ones have been seen before. That makes it possible, in principle, to flag a phishing domain the moment it's registered, without waiting for a human report.

Machine learning algorithm

The classifier is a Random Forest — an ensemble of decision trees, each trained on a bootstrapped sample of the training data and a random subset of features. Predictions are made by majority vote across all trees, which reduces the overfitting risk of any single tree and tends to generalise well on structured, tabular feature sets like this one.

Random Forest was chosen over deep learning approaches for a few practical reasons:

  • The feature set is tabular and hand-engineered, not raw sequence or image data — the setting Random Forest is strongest in.
  • It trains quickly and doesn't require a GPU, which matters for a project meant to be reproducible on ordinary hardware.
  • Feature importance is directly interpretable, which supports the project's goal of explaining every verdict rather than hiding it behind a black box.

Training data combines lexical features (URL length, character entropy, hyphen and digit counts, special characters), structural features (subdomain depth, presence of an IP address host, non-standard ports), and host-based features (HTTPS/TLS status, WHOIS and DNS signals) drawn from labelled phishing and legitimate URL datasets.

Technology stack

Frontend

HTML5, CSS3, Vanilla JavaScript — no frameworks. Hand-rolled SVG charts and gauges, glassmorphism UI.

Backend

Python 3 with Flask, exposing a versioned REST API for scan requests and health checks.

Machine learning

scikit-learn's RandomForestClassifier, with pandas and NumPy for feature engineering and preprocessing.

Data & storage

CSV-based training dataset for the model; browser localStorage for client-side scan history in this build.

System architecture

The frontend and backend are fully decoupled and communicate only over HTTP via a documented REST contract — the frontend never depends on backend internals.

🖥 Frontend HTML / CSS / JS
→
🔗 REST API POST /api/scan
→
🐍 Flask backend Feature extraction
→
🌲 Random Forest Trained model
→
📊 JSON verdict Rendered in UI

Until the backend is deployed, the frontend runs against a local heuristic scorer with an identical response shape, so the UI is fully demoable standalone — see frontend/js/api.js.

Benefits

  • Can flag newly-registered phishing domains that blocklists haven't caught up to yet.
  • Explains every verdict with feature-level reasoning instead of a single opaque label.
  • Catches brand impersonation attempts through string-similarity matching, not just keyword rules.
  • Lightweight enough to run inference in well under a second, suitable for real-time use.
  • Clean REST contract makes the detection engine reusable outside this specific frontend — browser extensions, Slack bots, or other tools.

Limitations

  • Model quality is bounded by training data — it can underperform on phishing patterns not represented in the dataset.
  • URL-based features alone can't catch phishing delivered through means other than a link (e.g. malicious attachments).
  • WHOIS and DNS lookups require live network access and third-party services in production, introducing latency and rate limits.
  • Sophisticated attackers can adapt URL structure specifically to evade known feature patterns.
  • The trusted-brand registry used for impersonation detection needs ongoing maintenance to stay current.

Future improvements

  • Incorporate live page content analysis (DOM structure, form targets) in addition to URL-only features.
  • Add a browser extension for inline link checking before a user clicks.
  • Expand the trusted-brand registry and automate its maintenance from a curated threat-intel feed.
  • Support model retraining from user-submitted feedback on false positives/negatives.
  • Add authenticated multi-user accounts with server-side scan history instead of local-only storage.
